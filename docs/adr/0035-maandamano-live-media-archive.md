# ADR-0035: Maandamano tracker — live media embeds, misinfo-checked, with an archive

**Status:** Proposed · **Date:** 2026-10-05
**Amends (additive):** ADR-0007 (maandamano tracker: safety, legal posture, data model). Additive — it adds embed-only media, a misinfo check on every embed, a status-history table and an archive read model. It does **not** change the `demonstrations` table's existing columns, the `MaandamanoResponse` shape, the `GET /v1/maandamano` contract, or the kill-switch premise. ADR-0007's safety rule ("show what's happening and where, never who is where; protester safety before engagement; locations stay ward-coarse") and its kill-switch (AT-0007-A) bind everything here unchanged.

## Problem
ADR-0007 made the tracker a text-only, editor-curated advisory list. The dominant maandamano misinformation vector is **recycled/miscontextualized footage** — an old clip passed off as a current event (ADR-0032 §1b: "reverse-image-search is the top check" **[V]**). A tracker that cannot carry the media of unfolding events, and cannot flag a recycled clip, cedes that ground. We need to (1) carry media of unfolding events, (2) run every piece of that media through the existing synthetic-media / reverse-image check, and (3) archive advisories as they conclude — all **without** re-hosting footage, loosening ward-coarse geography, breaking the kill-switch, or auto-publishing protest locations.

## Context / evidence
- **Embeds, never re-hosting.** ADR-0002 (no third-party audio download) and ADR-0027 ("never re-hosted": a published check links to the original platform post, never a copy) already set the rule; ADR-0032 §32 notes the TikTok **oEmbed** path (embed + metadata only, no discovery, no audio) as the compliant one. Embedding licensed broadcasters' streams fits the CA-ban precedent ADR-0007 cites. **[V: ADR-0002/0007/0027/0032 reads]** Legal (platform ToS + copyright) favours iframe embeds over re-hosted bytes.
- **The misinfo check already exists.** `services/pipeline` has a `ReverseImageSearch` protocol (`find_earlier_copy`), a `SyntheticMediaTriageResult` model, and ADR-0032 AT-0032-8 already wires "earlier-dated footage match → evidence" into the verify hop using a thumbnail/frame hash "where available". An embed is checkable the same way, from its platform thumbnail/metadata, with no re-host. **[V: verify.py / pipeline_io.py reads]**
- **The kill-switch is one server-side gate.** `getMaandamanoAdvisories(db)` reads the `maandamano_kill_switch` policy flag first and, when frozen, returns `{ frozen: true, demonstrations: [] }` **without ever querying the `demonstrations` table** (`services/api/src/lib/maandamano.ts`, proven by `maandamano-killswitch.integration.test.ts`). Because media and archive hang off demonstrations behind this same gate, the kill-switch covers them for free if they are read through the same function. **[V]**
- **States already exist:** `rumoured → announced → confirmed → ongoing → ended → cancelled` (`DemonstrationStatusSchema`). **[V]**

## Options
1. **Re-host clips** (download, store, serve from our bucket). — ✓ full control of playback/retention ✗ ToS/copyright/account-ban exposure (ADR-0002 irreversible), storage + CSAM/NCII scanning burden (ADR-0027), and it contradicts "never re-hosted". Rejected.
2. **Iframe embeds to the source platform** — store `{platform, embedUrl, caption, observedAt}` + a misinfo-check status, never the bytes; every embed routed through the existing reverse-image/synthetic-media check; archive = the advisory + its status history + source/embed links, never raw media. — ✓ compliant, cheap, reuses the whole existing misinfo pipeline, kill-switch covers it through one gate ✗ playback depends on the platform (a deleted source clip 404s), and a thumbnail-only reverse-image check is weaker than a full-frame one.
3. **Embeds but no misinfo check** — ✓ simplest ✗ leaves the single most important maandamano vector (recycled footage) unflagged; defeats the point. Rejected.

## Decision: Option 2
Media is **iframe embeds to the source platform**, misinfo-checked, archived as links. The `demonstrations` table is **not altered** — all additions are **new tables** and an optional contract field that defaults empty, so existing rows, the `MaandamanoResponse` shape, and the `GET /v1/maandamano` contract all keep validating.

- **Media model (additive).** `DemonstrationSchema` gains optional `media: DemonstrationMedia[]` defaulting to `[]`. `DemonstrationMedia = { id, platform: "youtube"|"x"|"tiktok", embedUrl (host-allowlisted to the platform's embed/oEmbed host — never an arbitrary or self-hosted URL), caption (nullable, ≤280), observedAt, misinfoStatus: "unchecked"|"checking"|"clear"|"flagged", misinfoNote (nullable) }`. Backed by a new `demonstration_media` table (FK to `demonstrations`, `onDelete: cascade`) — **no media bytes, ever**.
- **Privacy reconciliation (ADR-0007 unchanged).** An embed attaches to an advisory whose `area` stays **ward/sub-county coarse**; the embed does not refine geography. The embed is of an **already-public platform post** (the poster chose to publish). Editors must not caption with sub-ward location ("what's happening, not who is where"). No GPS/EXIF concern — nothing is uploaded or re-hosted.
- **Misinfo check on every embed (the point).** Attaching an embed enqueues a job to `services/pipeline` that runs the **existing** `ReverseImageSearch`/synthetic-media triage on the embed's platform **thumbnail/frame hash + metadata** (ADR-0032 §1b, no re-host). The result writes back `misinfoStatus` (`clear`/`flagged`) + `misinfoNote` ("earlier copy seen {url} {date} — consistent with recycled/miscontextualized footage"). A `flagged` embed renders a caveat badge on the advisory. **Optional escalation:** a flagged embed can spawn a normal `Check` (`ingest_source: "fetch"`) tied via the existing `checks.demonstration_id` FK, reusing the full verify + ADR-0023 framing + ADR-0034 context pipeline to publish a "this clip appears recycled" assessment. The badge is the minimum; the `Check` is the richer reuse.
- **Archive read model (additive).** Archive = the advisory + its **status history** + source/embed **links** — never raw media (embeds are links, so this holds trivially). A new append-only `demonstration_status_events` table records each status change in the **same transaction** as the `demonstrations.status` update, so the timeline is real rather than reconstructed. A new `GET /v1/maandamano/archive` returns `ended`/`cancelled` advisories with their status history, sources and embed links. It is **kill-switch-gated through the same frozen check** as the live list.
- **States — confirmed, no gap for this feature.** `rumoured → announced → confirmed → ongoing → ended → cancelled` covers the brief's vocabulary: **"planned"** = `announced` (publicly called) or `confirmed` (Public Order Act Cap 56 s.5 notice to the regulating officer, ADR-0007); **"active"** = `ongoing`; archive terminal states = `ended`/`cancelled`. No new enum value is required. Minor noted gap (not blocking, not implemented here): there is no distinct `postponed`/`rescheduled` state — today that is a `cancelled` row plus a new `announced` row, which the status-history table now records faithfully.
- **Ingestion boundary (human-curated, non-negotiable).** Advisories stay **human-curated**. The fetch engine (ADR-0032) MAY surface maandamano-salient trending clips to a **read-only editor-suggestion surface** (its salience list already includes maandamano terms, ADR-0032 §48/§119). It MUST NOT auto-create or advance a demonstration, attach an embed, or publish a location. Enforced structurally: **no `services/pipeline`/fetch code path writes `demonstrations`, `demonstration_media`, or `demonstration_status_events`** (the same "no such code exists" discipline as ADR-0030's funnel firewall). Attaching an embed or changing a status is only ever an authenticated editor/admin POST.

## Trade-offs accepted
1. **Platform-dependent playback.** A source clip deleted/removed on YouTube/X/TikTok 404s in our embed; we keep the caption + misinfo status + archive link, but we do not control availability. Accepted — the alternative (re-host) is the ADR-0002 irreversible we refuse.
2. **Thumbnail-only reverse-image is weaker than full-frame.** For an embed we hash the platform thumbnail/metadata, not downloaded frames (no re-host), so a recycled clip re-encoded with a fresh thumbnail can slip the check. Accepted; the flag is a strong-signal aid to a human editor, not an automated verdict.
3. **Async flag, not pre-attach block.** An embed can be live on an advisory before its misinfo check returns (`misinfoStatus: "checking"`). Mitigation: the editor attaches deliberately (human-curated), the badge updates on callback, and the kill-switch can freeze the whole surface instantly.

## Irreversible
None introduced. New tables + an optional contract field; the kill-switch still halts the whole surface. We deliberately avoid the ADR-0002 irreversible (account bans from scraping/re-hosting) by embedding only.

## Review trigger
Revisit on the first takedown/ToS complaint about an embed, after a legal opinion on third-party republication of protest schedules (ADR-0007's open GAP), or if thumbnail-only reverse-image proves too weak in practice (then weigh a licensed/partner full-frame path).

## Delegation notes (for the implementing pass — do not re-litigate embed-only or human-curation)

**Schema / contract / migration (EXPAND-only — all additions are NEW tables; `demonstrations` is untouched):**
1. `packages/core/src/schemas/demonstration.ts`:
   - Add `DemonstrationMediaSchema = z.object({ id: z.string().uuid(), platform: z.enum(["youtube","x","tiktok"]), embedUrl: z.string().url().refine(isPlatformEmbedHost), caption: z.string().max(280).nullable(), observedAt: z.string().datetime(), misinfoStatus: z.enum(["unchecked","checking","clear","flagged"]), misinfoNote: z.string().max(500).nullable() })` with a host-allowlist refine (`youtube.com/embed`, `youtube-nocookie.com`, `platform.twitter.com`/`x.com`, `tiktok.com/embed` — reject any other host, which is what blocks a re-hosted URL).
   - Add `media: z.array(DemonstrationMediaSchema).default([])` to `DemonstrationSchema` (optional default `[]` → existing rows and the `MaandamanoResponse` shape keep validating).
   - Add `DemonstrationStatusEventSchema = z.object({ status: DemonstrationStatusSchema, note: z.string().max(500).nullable(), occurredAt: z.string().datetime() })`.
   - Add `MaandamanoArchiveResponseSchema = z.object({ frozen: z.boolean(), archived: z.array(DemonstrationSchema.extend({ statusHistory: z.array(DemonstrationStatusEventSchema) })) })`.
2. `packages/db/src/schema.ts` (new tables only — **do not ALTER `demonstrations`**):
   - New enum `demonstrationMediaMisinfoStatusEnum = pgEnum("demonstration_media_misinfo_status", ["unchecked","checking","clear","flagged"])` (mirror the zod enum, same single-source discipline as the other enums).
   - New table `demonstration_media` `{ id uuid pk, demonstrationId uuid → demonstrations(id) onDelete cascade, platform text, embedUrl text, caption text null, observedAt timestamptz, misinfoStatus demonstrationMediaMisinfoStatusEnum default 'unchecked', misinfoNote text null, reverseImageEarlierUrl text null, createdAt timestamptz default now() }`, index on `demonstrationId`.
   - New table `demonstration_status_events` (append-only, same discipline as `review_actions`) `{ id uuid pk, demonstrationId uuid → demonstrations(id) onDelete cascade, status demonstrationStatusEnum, note text null, changedBy uuid → users(id) null, occurredAt timestamptz default now() }`, index on `(demonstrationId, occurredAt)`.
   - `drizzle-kit generate` → the migration must be `CREATE TYPE … ; CREATE TABLE demonstration_media … ; CREATE TABLE demonstration_status_events …` only (no `ALTER TABLE demonstrations`).
3. `pnpm gen:contracts` — regenerate the JSON Schema + `services/pipeline/app/models/generated.py` so the Python side sees `DemonstrationMedia` (the pipeline needs it for the misinfo callback payload).

**API (`services/api`):**
4. `services/api/src/lib/maandamano.ts`:
   - `getMaandamanoAdvisories`: extend `toDemonstration` + the query to LEFT JOIN `demonstration_media` and attach `media` (default `[]`). **Leave the frozen branch exactly as is** — it returns `demonstrations: []` without reading the table, so media is frozen for free.
   - New `getMaandamanoArchive(db)`: read the kill-switch flag FIRST (reuse `isMaandamanoFrozen`); if frozen return `{ frozen: true, archived: [] }` without touching any demonstration table; else select `status IN ('ended','cancelled')` + join `demonstration_status_events` (ordered) + `demonstration_media` links, newest-ended first.
   - New `attachDemonstrationMedia(db, { actorId, demonstrationId, platform, embedUrl, caption, observedAt })`: insert a `demonstration_media` row (`misinfoStatus: 'unchecked'`) and an `audit_log` row in one transaction (reuse the audited-mutation pattern), then enqueue a misinfo-triage job (QStash) to `services/pipeline`.
   - New `recordDemonstrationStatus(db, { actorId, demonstrationId, status, note })`: update `demonstrations.status` **and** insert a `demonstration_status_events` row in the same transaction.
   - New `applyMediaMisinfoResult(db, { mediaId, status, note, earlierUrl })`: pipeline → API write-back for the embed's check result.
5. `services/api/src/routes/maandamano.ts` (extend, do not break the existing `GET /v1/maandamano`):
   - `GET /v1/maandamano/archive` — public, `no-store`, kill-switch-gated → `getMaandamanoArchive`.
   - `POST /v1/admin/maandamano/:id/media` — `requireRole(auth, ["admin","editor"])` → `attachDemonstrationMedia` + `triggerMaandamanoRevalidation`.
   - `POST /v1/internal/maandamano/media/:mediaId/misinfo` — secret-gated pipeline callback → `applyMediaMisinfoResult` + revalidate.
   - (Status changes go through an editor endpoint calling `recordDemonstrationStatus`; if no demonstration-CRUD route exists yet, add the status-change POST here, admin/editor-gated.)

**Pipeline (`services/pipeline`):**
6. Add a media-triage entry point (new `POST /hops/media-triage`, or extend the reverse-image path) that takes `{ mediaId, platform, embedUrl, thumbnailRef }`, runs the existing `ReverseImageSearch.find_earlier_copy` / synthetic-media triage on the **platform thumbnail/metadata only** (no download of third-party audio/frames — ADR-0002), and POSTs the result back to the internal route in step 5. Reuse `SyntheticMediaTriageResult`; do not add a new detector.
7. **Ingestion boundary enforcement:** ensure **no** `services/pipeline`/fetch-engine code writes `demonstrations`/`demonstration_media`/`demonstration_status_events`. Maandamano-salient fetch candidates surface only in a read-only editor-suggestion view (reuse `fetch_candidates` with a salience tag). Attaching/advancing is always a human editor/admin POST.

**FE (apps/web, note only):**
8. `apps/web/app/maandamano/page.tsx` — render each advisory's `media` as sandboxed iframe embeds, with a caveat badge ("⚠ may be recycled footage — earlier copy seen {date}") when `misinfoStatus === 'flagged'`. Add a `/maandamano/archive` view (ended/cancelled advisories + status timeline + embed/source links). The existing `NetworkOnly` service-worker rule for `/maandamano*` already covers the archive route (no offline cache of a frozen surface).
