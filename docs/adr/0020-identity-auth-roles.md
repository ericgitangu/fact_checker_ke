# ADR-0020: Identity, auth and roles

**Status:** Proposed · **Date:** 2026-10-03 · Gates ADR-0009/0011 per-user quotas and ADR-0018 SSE capability tokens

## Problem
ADR-0015 says "later auth", ADR-0018 says "capability token, later auth", but ADR-0009 and ADR-0011 already enforce *per-user* quotas and ADR-0007/0008 need editor and admin roles with accountability. "Later" has no definition, and per-IP is the only fallback today, which breaks under Safaricom CGNAT (red-team C-9: many subscribers share one egress IP). This ADR defines the identity model for three populations: anonymous submitters/readers, optional registered accounts (later), and editor/admin staff (now).

## Evidence
- Red-team E: "Auth and identity... 0009 and 0011 enforce per-user quotas. Per-user of what? Per-IP is the only fallback, and it breaks under mobile CGNAT (C-9)." **[U, from report]**
- Clerk free tier: "50,000 MRU limit per app"; MFA is **not** included free (Pro+ only); 1-day log retention **[V: clerk.com/pricing, fetched 2026-10-03]**.
- Firebase Auth / Identity Platform Spark plan: "No-cost up to 50K MAUs" for standard sign-in; phone auth is billed per SMS with no stated free SMS allowance **[V: firebase.google.com/pricing, fetched 2026-10-03]**.
- Better Auth (self-hosted, open source) ships a 2FA plugin: "OTP... or TOTP... A code generated by an app on the user's device" **[V: better-auth.com/docs/plugins/2fa, fetched 2026-10-03]**. It stores its own tables in our Postgres (Neon), so it has no vendor MAU metering at all — the cost is rows we already pay for.
- Auth.js (NextAuth) has no built-in MFA; TOTP would be a third-party adapter, unverified **[GAP]**.
- Mobile talks to the API directly (ADR-0015), so whatever auth scheme exists must be usable from a Fastify API, not just from Next.js middleware.

## Options
1. **Clerk for everything.** Rejected: MFA (required for editors/admins) is paid-only, and 50K MRU is wasted on a 1-3 person editor team. The hosted session cookie also assumes a Next.js-fronted flow mobile-direct-to-API (ADR-0015) doesn't get for free.
2. **Firebase Auth / Identity Platform for everything.** Rejected: MFA cost is **[GAP]**, and it's a second cloud identity (GCP) beside Neon/Upstash with no gap it fills for a 1-3 person team.
3. **Better Auth, self-hosted in Neon, for editors/admins; no vendor identity product for anonymous users. Recommended.** TOTP MFA is free, open source, no MAU metering — cost is Neon storage already paid for. Runs as a Fastify plugin in `services/api` so mobile and web share `/v1/auth/*`.
4. **Custom auth from scratch.** Rejected: reinventing session rotation and TOTP is "novel tech" the cost-discipline rule forbids without a gap Better Auth doesn't close.

## Decision (proposed)
1. **Anonymous submit/read, no account required.** On first contact, `services/api` issues an opaque **device token** (256-bit random, hashed in Postgres `device_tokens(token_hash, created_at, last_seen_at)`, mirrored to a short Redis `SET NX` for dedup) via an HttpOnly cookie (web) or mobile secure storage. This token, **not the client IP**, is the quota key for ADR-0011/0009's per-user caps. IP stays only a coarse ceiling (≥50 req/min) so CGNAT users aren't blocked by IP alone — closing C-9.
2. **SSE capability tokens (ADR-0018)** are short-lived JWTs signed by the API, scoped to one `submission_id`, expiring at stream close (≤90s + resume). Minted from the device token at submission time; never valid cross-submission.
3. **Optional registered accounts, Phase 2+.** Better Auth email/passkey sign-in, linked to the device token's prior history. Out of scope now; schema (`users`, `accounts`, `sessions`) reserved so the migration is additive.
4. **Editor/admin RBAC, required before any named-person "False" ships (ADR-0008 C-13).** Roles: `editor` (draft review, publish, correct), `admin` (editor + role grants, kill-switch per ADR-0007). **MFA (TOTP) is mandatory for both** — no role grant without a verified enrollment, enforced server-side.
5. **Immutable audit log.** Every role grant, publish, correction, kill-switch flip and login is an append-only `audit_log(id, actor_id, action, target_type, target_id, metadata, created_at)` row, written in the same transaction as the action (reuses the ADR-0017 outbox pattern). No update/delete grant exists at the DB-role level.
6. **Quota keys:** anonymous = device token; authenticated reader = account id (falls back to pre-login device history); editor/admin actions skip the public quota path.

## Trade-offs accepted
Self-hosted auth means we own session rotation, token revocation and the TOTP recovery flow instead of buying it. Accepted because the editor headcount is tiny, MFA must be free, and it avoids a second vendor dependency when Neon is already the source of truth.

## Irreversible
Device-token-as-quota-key is a schema and client contract (mobile stores it) — changing the quota key later requires a migration that preserves existing users' standing, not a breaking reset.

## Review trigger
Revisit if MAU for the optional-accounts feature approaches Firebase's or Clerk's free-tier ceiling, or if a second admin/editor hire changes the MFA-enrollment UX cost calculus.

| ID | Behaviour | Status |
|---|---|---|
| AT-0020-1 | Two distinct devices behind the same CGNAT IP each get their own quota standing; neither is throttled by the other's usage | RED |
| AT-0020-2 | An SSE capability token minted for submission A is rejected (403) on a request for submission B's stream | RED |
| AT-0020-3 | A role grant to `editor` or `admin` is rejected unless the target account has a verified TOTP enrollment | RED |
| AT-0020-4 | Every publish, correction and kill-switch flip produces exactly one `audit_log` row in the same transaction as the action; a rolled-back action produces zero rows | RED |
| AT-0020-5 | A device token rotated/lost by the client starts a fresh quota identity (no silent quota inheritance via IP) | RED |
